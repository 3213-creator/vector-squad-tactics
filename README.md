# DEATH MATCH — 실시간 1 대 1 FPS

업로드된 3D 맵에서 각자 1인칭 카메라로 이동·점프·조준·교전하는 브라우저 FPS입니다. 턴이나 AP, 칸 이동은 없습니다. PRESS START → 이름/메뉴 → 방 생성·참가 → 로비 → AI 출격 또는 양쪽 준비 → 실시간 결투 → 리스폰/승패 → 로비 흐름입니다.

게임: https://vector-squad-tactics.onrender.com

## 조작

| 기능 | 키 |
|---|---|
| 이동 | W / A / S / D |
| 시점 조준 | 마우스 이동 (전투 시작 시 마우스 잠금 허용) |
| 발사/연사, 칼 공격 | 터치패드 한 손가락 탭 / 왼쪽 클릭, 클릭을 누르면 연사 |
| 총기 정조준 | Shift 누르는 동안 (일반 총은 부착 조준경, 저격총은 스코프) |
| 점프 | Space |
| 달리기 | W 빠르게 두 번 (칼은 Shift도 지원) |
| 장전 | R |
| 주무기 / 권총 / 칼 | 1 / 2 / 3 또는 마우스 휠 |
| 빠른 근접 공격 | V |
| 수류탄 | G |
| 마우스 해제/일시 조작 중지 | Esc |

전투의 클릭 버튼은 마우스 잠금을 시작하기 위한 버튼입니다. 전투 조작을 활성화한 뒤에는 터치패드 탭/왼쪽 클릭으로 발사하며 누르고 있으면 연사합니다. 마우스 잠금이 차단된 환경에서는 새 탭으로 게임을 열거나 제공되는 드래그 조작 대안을 사용하세요. 터치 기기는 조이스틱/화면 드래그/발사·점프 버튼도 제공합니다.

조준선은 고정 중앙 점이 아니라 총구에서 발사되는 광선이 맵/상자에 닿는 지점을 화면으로 투영한 표시입니다. 서버도 같은 총구 위치와 방향에서 명중을 판정합니다. 저격 스코프를 켜면 광학 조준축과 좁은 FOV를 사용합니다.

## 전투 규칙

각 플레이어는 시작 목숨 3개이며 목숨 하나의 HP는 100입니다. 사망하면 목숨을 하나 차감하고 남아 있으면 5초 후 HP 100으로 리스폰합니다. 리스폰 후 보호 시간은 3초입니다. 마지막 목숨을 잃으면 상대 승리이며 3초 후 두 명 모두 같은 방의 로비로 돌아갑니다. 이름과 주무기 선택을 유지하고 새 결투는 다시 3목숨으로 시작합니다.

| 무기 | 몸통 | 헤드 | 연사 | 탄창 | 장전 |
|---|---:|---:|---:|---:|---:|
| AR-01 라이플 | 30 | 60 | 600 RPM | 30 | 1.8초 |
| SR-08 저격총 | 85 | 110 | 50 RPM | 5 | 2.6초 |
| P-09 권총 | 18 | 40 | 300 RPM | 12 | 1.2초 |
| K-01 칼 / 빠른 근접 | 40 | 100 | 칼 90 RPM / V 0.8초 간격 | 없음 | 없음 |

칼/근접 공격은 뒤치기도 100 피해입니다. 총은 서버가 머리/몸통 히트박스, 벽 가림, 총구까지의 가림, 사거리, 연사 간격, 탄약과 장전 시간을 검증합니다. 수류탄은 목숨당 2개, 지연 2.2초, 반경 4m이며 거리에 따라 최대 100에서 감소하고 맵 벽은 폭발 피해를 차단합니다.

매 경기 서버가 지상 빈 공간에서 8개의 보급 상자 위치를 무작위로 고릅니다. 칼 또는 V로 부수고 나온 물품에 1.25m 이내로 다가가면 자동 획득합니다. 탄약은 현재 총의 예비탄 +30(칼을 든 경우 주무기), 약물은 남은 목숨 +1이며 HP를 회복하지 않습니다. 추가 목숨으로 3개를 넘길 수 있고 HUD에 반영됩니다. 상대도 먼저 보급품을 획득할 수 있습니다.

## 로컬 실행

Node.js 22:

```sh
npm ci
npm start
```

http://localhost:3000을 두 브라우저에서 열어 같은 방 코드로 참가합니다. 다른 기기는 서버 컴퓨터의 IP:3000으로 접속합니다. 배포 시에는 Render가 제공하는 HTTPS URL을 사용합니다.

## GitHub / Render

저장소 최상위에 package.json, package-lock.json, server.js, game.js, physics.js, collision-world.js, world.js, map-data.js 및 public/ 전체가 있어야 합니다. node_modules는 업로드하지 않습니다. public/assets의 GLB도 포함해야 합니다.

| Render 항목 | 값 |
|---|---|
| 서비스 | Node Web Service |
| Branch | main |
| Root Directory | 비워 두기 |
| Build Command | npm ci |
| Start Command | npm start |
| NODE_ENV | production |

PORT는 Render가 주입하고 서버는 0.0.0.0에 바인딩합니다. 서버 하나가 HTML·JS·GLB·WebSocket을 모두 제공합니다. HTTPS에서는 자동 WSS를 사용합니다. /healthz는 HTTP 상태 확인 경로이고 직접 생성한 현 서비스의 기본 헬스 체크는 TCP입니다. render.yaml은 선택적으로 새 Blueprint를 만들 때 쓰는 설정입니다.

## 구현 및 검증

- 서버 물리/입력 30Hz, 상태 스냅샷 15Hz. 렌더링과 별개로 입력을 전송하고, 입력 시퀀스와 서버 확인 번호로 클라이언트 이동 예측을 보정합니다.
- 공유 캡슐 물리, 중력, 점프, 바닥/벽 접촉과 보급 상자 충돌을 사용합니다. 실제 GLB에서 생성한 간소화 충돌 모델을 BVH로 검색합니다. 맵의 시각 모델도 정적 메시를 병합해 드로콜을 줄였습니다.
- 브라우저는 픽셀 비율 1 및 최대 30fps 렌더링을 사용합니다. 상대 위치는 보간하고 스킨 애니메이션을 재생합니다.
- 정적 에셋은 시작 시 캐시하고 gzip 전송합니다. 맵/캐릭터에 버전 쿼리와 브라우저 캐시를 적용합니다.
- 연결 최대 220(재연결 여유 포함), 방 최대 100, 메시지 4KB를 허용합니다. 입력 제한은 초당 120개 보충/최대 240개 토큰으로 순간 폭주를 흡수하며 초과분은 연결 종료 없이 버립니다. 최신 입력만 유지하고 300ms 무입력 시 정지합니다. 송신 적체 64KB부터 상태 패킷 전송을 건너뛰고, 15초 간격 ping/45초 무응답 감지 및 SIGTERM 종료를 제공합니다.
- `npm test`는 실제 맵 물리, 무기/헤드샷, 장전, 3목숨/리스폰, 상자 보상, 두 WebSocket 입력 동기화를 검증합니다. GitHub Actions가 push/PR에서 실행합니다.

무료 Render의 절전 및 콜드 스타트는 남습니다. 방 상태는 메모리에만 있어 서버 재시작 시 초기화되며 단일 인스턴스로 실행해야 합니다. 계정·영속 저장·지연 보상/과거 시점 명중 판정은 아직 없습니다. 미니맵의 상대 위치는 공개됩니다.

3D 출처와 업로드 모델 정보는 CREDITS.md에 있습니다. 맵의 시각 GLB와 충돌 GLB를 바꿀 때에는 좌표·축척을 맞추고 물리 테스트도 갱신해야 합니다.

## 상호작용 및 전투 연출

- 모델의 앞 방향과 시야를 일치시키고 전진/후진/좌우 이동 애니메이션을 구분합니다.
- 칼은 옆으로 휘두르는 근접 모션을 재생하며 총 발사 이벤트나 섬광, 탄흔을 만들지 않습니다.
- 총을 벽에 맞히면 양쪽 화면에 탄흔이 남습니다. 경기당 최근 48개로 제한하고 다음 경기에서 초기화합니다.
- 기존 두 사다리는 가까이에서 F로 잡고/놓으며 W/S로 오르내리고 Space로 뛰어내립니다. 꼭대기에서 실제 옥상으로 올라섭니다.
- 기존 네 건물의 문은 바라보고 W로 접근하면 열립니다. 시각 모델과 충돌 모델 모두에 실제 출입구를 만들었으므로 건물 안으로 이동할 수 있습니다.
- 장전은 총 기울이기, 탄창 분리/삽입, 장전 손잡이 동작으로 이어지며 서버의 장전 시간과 동기화합니다.

## 부활 보급과 코인

매 경기 각자 300코인으로 시작합니다. 코인은 로비 및 전투 화면 왼쪽 위에 표시되고, 사망 후 무료 자동 부활까지 5초 동안 아래 보급품을 각각 50코인에 구매할 수 있습니다. 즉시 부활 상품은 없습니다. 구매한 코인은 리스폰해도 차감된 상태를 유지하며 다음 경기 시작 시 300으로 초기화됩니다. 같은 보급품은 해당 부활 대기 중 한 번만 구매할 수 있습니다.

| 보급품 | 다음 목숨 효과 |
|---|---|
| 강화탄 | 총 피해 +10% |
| HP UP | 별도 보호막 +20. 기본 HP는 100 유지 |
| 투시경 | 부활 후 8초간 상대를 벽 너머로 표시 |

구매하지 않아도 자동 부활합니다. 부활 후 3초 동안 파란 불투명 방어막이 바깥을 감싸고 서버가 모든 피해를 차단합니다. 안쪽 면은 렌더링하지 않아 자신의 1인칭 시야는 가리지 않으며, 본인 화면에는 파란 테두리와 보호 안내가 표시됩니다. 마지막 목숨을 잃은 경우에는 구매 메뉴 없이 승패를 표시하고 로비로 이동합니다.

## 공간 음향

공개 라이선스의 녹음 총소리(라이플/저격총/권총), 발소리와 수류탄 취급/폭발음을 로컬 WAV로 제공합니다. 출처·저작자·라이선스·편집 내역은 로비의 사운드 출처 링크 및 public/audio/CREDITS.md에 있습니다. 칼 공격 소리는 재생하지 않습니다.

서버가 실제 이동 거리와 접지 상태로 발걸음 이벤트를 생성하고, 발사/투척/폭발의 월드 좌표도 전송합니다. 브라우저의 Web Audio HRTF Panner가 사용자 눈 위치/시선에 맞춰 좌우·앞뒤 방향과 거리 감쇠를 적용하며 벽 뒤 소리는 저음 통과 필터와 감쇠를 적용합니다. PRESS START 또는 전투 시작 클릭에서 오디오를 활성화하고 로비/전투의 소리 버튼으로 끌 수 있습니다. 동시 음원은 최대 32개입니다.

수류탄은 G 입력 뒤 300ms 동안 손으로 쥐고 팔을 당긴 후 발사되며, 총 650ms의 투척 모션 뒤 총을 다시 듭니다. 투척 속도는 18m/s이며 위쪽 힘 5m/s를 추가합니다. 조준 각도·중력·충돌·튕김을 적용하며 도화선은 2.2초입니다.

## 첫 화면 / 브랜드

연기 구체로 만든 시작 장면을 제거하고, 사용자가 제공한 전투 장면 레퍼런스를 바탕으로 제작한 사막 전장 배경을 사용합니다. 첫 화면과 로비 헤더는 같은 긁힌 금속/구리색 테두리의 DEATH MATCH 워드마크를 사용합니다. 시작 화면은 정적 이미지로 표시해 불필요한 3D 렌더링도 하지 않습니다.


## AI / PVP 모드와 미니맵

로비 중앙 위의 AI 훈련 / PVP 대전 버튼에서 방장이 모드를 선택합니다. 혼자 접속하면 기본 AI, 두 번째 실제 플레이어가 로비에 접속하면 자동 PVP로 바뀝니다. AI 모드는 별도 방 참가 없이 게임 시작 버튼을 누르면 자동으로 개인 방에 접속해 시작합니다. 이름이 없으면 이름 저장 직후 이어서 출격합니다. PVP는 두 플레이어 모두 준비해야 시작됩니다. AI 전투 중 친구를 초대하려면 전투 우측 상단의 로비로 버튼으로 돌아오세요.

AI는 서버에서 실제 맵의 보행 가능 영역을 탐색해 순찰하고, 시야와 벽 가림을 검사해 플레이어를 발견하면 반응 지연 후 조준·점사합니다. 이동/피해/장전/탄약/부활 보호는 플레이어와 같은 규칙을 사용합니다.

오른쪽 아래 미니맵 배경은 업로드된 실제 맵을 위에서 렌더링한 이미지입니다. 자신의 이동 위치와 바라보는 방향만 표시하며, 1번 플레이어는 파란 점, 2번 플레이어는 빨간 점입니다. 상대와 AI 위치는 표시하지 않습니다. 투시경 구매도 미니맵 적 표시를 켜지 않습니다.

상자는 칼뿐 아니라 총알로도 파괴할 수 있습니다. 상자 HP는 55이며 총기 피해가 누적됩니다. 벽 너머 상자는 타격할 수 없고 상자가 총알을 막습니다. 파괴 후 접근하면 기존 보상인 예비탄 +30 또는 목숨 +1을 받습니다.


## 세 슬롯 무기고 / 첨부 총기 9종

로비 하단에는 주무기·보조무기·근접무기 바 세 개가 있습니다. 바를 누르면 무기 선택 창이 열리고, 실제 첨부 GLB에서 렌더링한 아이콘과 피해/연사/장탄 스탯을 보고 선택합니다. 주무기는 라이플 2종·기관단총 2종·저격총 2종, 보조무기는 권총 2종·리볼버 1종, 근접무기는 기존 전투 나이프입니다. 선택 창은 클릭·터치를 지원하고 닫기 버튼, Escape, 창 바깥 클릭으로 닫습니다.

선택한 주무기와 보조무기는 독립적으로 보존되며 서버 접속·부활·로비 복귀 후에도 유지됩니다. 전투는 주무기를 들고 시작하며, 1번은 선택한 주무기, 2번은 선택한 보조무기, 3번은 칼입니다. 휠과 HUD 버튼도 이 세 슬롯 사이를 전환합니다. 두 저격총 모두 Shift를 누르는 동안 스코프를 켜며 놓으면 즉시 일반 시야로 돌아옵니다.

전투 1인칭 뷰는 간단한 상자형 총 대신 첨부한 9개 GLB를 그대로 사용합니다. 모델마다 다른 크기·좌표축·총구 방향을 미터 단위의 -Z 전방으로 보정하며, 총기별 탄약·피해·장전 속도와 공간 음향을 적용합니다. 공통 탄창 교체/장전 손잡이/손 이동 모션은 모든 총에 같은 순서로 적용됩니다. 총기 카탈로그와 스탯은 weapons.js에서 관리합니다.


## 로비 / 전투 채팅

로비의 시작 버튼 위, 전투의 미니맵 위에 같은 방 채팅이 있습니다. M으로 입력창을 열고 Enter로 전송합니다. 사망 후 부활 대기 중에도 M 채팅이 가능하며 입력 중인 문장은 부활할 때 유지됩니다. 전투에서 입력 중에는 이동·발사·스코프가 멈추고, Enter 전송 또는 Escape 후 조작으로 돌아갑니다. 방 참가 전에는 메시지를 보낼 수 없습니다. AI는 채팅 응답을 하지 않습니다.

채팅은 서버가 발신자 이름을 붙여 같은 방의 실제 참가자에게만 전송합니다. 최근 30개를 로비/전투 사이에 유지하며 새 참가자에게 전달합니다. 메시지는 160자 제한, 750ms 전송 간격을 적용하고 화면에는 HTML로 해석하지 않는 일반 텍스트로 표시합니다.

모든 총기는 Shift 홀드로 조준하고 놓으면 일반 시야로 돌아옵니다. 조준과 달리기는 동시에 하지 않습니다. 칼을 들었을 때 Shift 달리기를 유지합니다. 모바일 조준 버튼도 누르는 동안만 조준합니다.


## 화면 전환 / 공개 전투 방

첫 화면에서는 전장 배경과 PRESS START만 보입니다. START를 누르면 금속 패널 메뉴로 이동합니다. 맨 위에 플레이어 이름을 입력하고 아래 경로를 선택합니다.

- HOST: 6자리 초대 코드가 있는 공개 방을 만들고 내 로비로 이동합니다.
- PUBLIC: 별도 공개 방 목록 화면으로 이동합니다. 금속 프레임 안의 행에 방장·방 코드·인원·상태를 표시합니다. 참가 가능한 행을 누르고 서버 참가가 성공하면 해당 방의 로비로 이동합니다.
- PRIVATE: 별도 코드 입력 화면으로 이동합니다. 존재하는 방 코드로 참가가 성공하면 로비로 이동합니다.
- 혼자 AI 훈련: 개인 AI 방의 로비를 만듭니다. 이 방은 공개 목록에 표시하지 않습니다.

메뉴·방 목록·코드 입력·로비·전투는 한 번에 하나의 화면만 표시합니다. 게임이 초기화되기 전에도 HTML hidden 속성과 CSS 숨김 규칙으로 첫 화면 외 UI를 숨깁니다. JavaScript가 CSS에 잘못 섞여 있던 스타일 파일을 복구했습니다. 메뉴와 방 목록에서는 3D 전투/로비 렌더링을 실행하지 않습니다.

방 목록은 해당 화면에 있을 때만 5초마다 갱신합니다. 가득 찼거나 전투 중인 방은 참가할 수 없습니다. 실패한 참가는 현재 화면에 오류를 표시하며 로비를 열지 않습니다. 방 나가기는 메뉴로 돌아오고, 전투의 로비로 버튼은 현재 방의 로비로 돌아옵니다. 로비 화면에서는 무기 선택·모드·채팅·게임 시작만 표시합니다.

### 화면 전환 검증

기본 서버/전투 검증: `npm test`

Chromium과 Playwright가 설치된 환경에서 `node scripts/check-navigation.mjs`를 실행하면 별도 로컬 서버를 띄워 화면 전환을 검증합니다. 필요하면 `PLAYWRIGHT_MODULE`에 설치된 Playwright 모듈 경로, `CHROMIUM_PATH`에 Chromium 경로를 지정합니다. 이미 실행한 서버는 `NAV_BASE_URL`로 지정할 수 있습니다. 기본적으로 소프트웨어 GPU로 인한 지연을 피하기 위해 테스트에서만 3D 프레임을 정지하며, 실제 GLB 로딩·방 API·WebSocket·DOM 전환은 그대로 검증합니다. 렌더링도 실행하려면 `NAV_RENDER=1`을 지정합니다. 스크린샷은 `NAV_ARTIFACT_DIR` 또는 `/tmp/death-match-navigation`에 저장됩니다.


## 총기별 정조준과 상대 전투 모션

저격총 2종은 기존 20도 FOV 스코프를 사용합니다. 나머지 7종은 실제 총 위에 서로 다른 3D 사이트를 장착하고 카메라·가늠자·가늠쇠를 일직선으로 정렬합니다. 총을 계속 표시하고 55~60도 FOV로 가볍게 확대하며, 전체 화면 저격 스코프나 일반 십자 조준점은 표시하지 않습니다.

| 무기 | 조준 방식 |
|---|---|
| AR-01 | 링형 가늠자 + 전방 가늠쇠 |
| AR-02 | AK형 개방 가늠자 + 가늠쇠 보호대 |
| SMG-01 | 원형 레드 도트 |
| SMG-02 | 개방형 그린 도트 |
| P-01 | 3점식 아이언 사이트 |
| P-02 | U형 가늠자 + 주황색 전방 표시 |
| R-06 | V형 가늠자 + 램프 가늠쇠 |

Shift를 놓거나 장전·칼 공격·채팅·사다리·사망 상태가 되면 조준을 해제합니다. 가늠자 높이와 총구 위치는 공유 프로필로 관리합니다. 조준 사격은 실제 총구에서 눈으로 본 지점을 향해 수렴하며, 총구가 낮은 엄폐물에 가리면 맞은편 적을 타격할 수 없습니다.

상대 플레이어와 AI는 public/remote-combat.js의 같은 표현 코드를 사용합니다. 서버 상태의 weapon, yaw/pitch, scoped, lastShot, reloadUntil을 읽어 실제 첨부 총 모델, 조준 높이·총구 방향, 발사 반동/섬광/짧은 예광, 탄창 분리/삽입 및 왼손 이동을 표시합니다. 기존 방향별 달리기와 사다리 애니메이션에 팔 IK와 시선 보정을 적용합니다. 칼 휘두르기·빠른 근접 공격·수류탄 투척도 표시하며 부활 후 선택한 무기를 다시 듭니다. 무기를 바꾸거나 방을 떠날 때 추가 모델과 재질을 해제합니다.


걷거나 달리는 동안은 총을 대각선으로 내려 들고 보폭에 맞춰 좌우·상하로 흔듭니다. 멈추면 정면 자세로 돌아오며, Shift 정조준 중에는 이동 흔들림을 억제합니다. W를 빠르게 두 번 누르면 W를 놓을 때까지 달리고, 조준·발사·장전·채팅·사다리에서는 달리기를 해제합니다. 상대방에게도 같은 이동/정지 자세가 표시됩니다.


수류탄은 1인칭에서도 장갑 낀 손과 손가락으로 쥐고 안전핀을 당긴 뒤 팔을 뻗어 던집니다. 서버의 throwAt/throwUntil에 맞춰 손에 있던 수류탄이 사라지는 순간 월드 투사체를 생성합니다. 상대에게도 손에 쥔 수류탄과 팔 동작이 보이며, 준비 도중 사망하면 투척이 취소됩니다.

탄창이 0이 되면 예비탄이 있는 경우에만 서버가 자동 장전을 시작합니다. 예비탄이 부족하면 있는 만큼만 채우며, 예비탄이 0이면 자동/수동 장전 모두 시작하지 않습니다. 화면에는 탄약 부족 안내가 표시됩니다.

검은 SWAT는 원본 GLB의 헬멧과 바이저를 그대로 사용합니다. 추가했던 눈·피부·천 마스크 등의 커스텀 얼굴은 제거했습니다.


## 첨부 FBX 대기 / 사망 모션

사용자가 제공한 Rifle Idle.fbx와 Dying.fbx의 본 모션을 변환하여 public/assets/rifle-idle.json과 dying.json으로 제공합니다. 원래 Soldier GLB에는 본이 없어, 원래 외형·색상을 유지한 채 SWAT 호환 뼈대와 스킨 웨이트를 추가한 soldier-rigged.glb를 생성했습니다.

로비의 두 군인은 모두 첨부한 Rifle Idle 클립을 반복하며 선택한 주무기를 손의 움직임에 맞춰 듭니다. FBX 축 방향을 보정해 로비에서 얼굴이 앞을 향하도록 표시합니다. 전투에서는 기존 이동/조준/장전 표현으로 전환합니다.

사망하면 캐릭터를 즉시 숨기지 않고 첨부한 Dying 클립을 재생한 뒤 쓰러진 상태를 유지합니다. 서버의 diedAt 시각을 기준으로 재생하므로 늦게 도착한 상태에서도 같은 모션 시점을 표시하며, 최종 승패 3초 전환에 맞춰 1.6배속으로 재생합니다. 본인 시야도 아래로 내려가며 기울어지고, 기존 5초 부활 또는 최종 로비 복귀 규칙은 유지합니다. 부활하면 대기/이동 자세와 무기를 다시 표시합니다.


로비의 두 캐릭터는 입장 시 정면을 향합니다. 실제 캐릭터를 마우스로 누르거나 터치한 채 좌우로 드래그하면 선택한 캐릭터만 회전합니다. 선택한 방향은 대기 모션과 무기 선택 중에도 유지되며 새 방에 들어가면 정면으로 초기화합니다. 회전 조작은 전투 카메라와 서버의 플레이어 방향에 영향을 주지 않습니다.


### 웅크리기 및 강화탄
C 키를 한 번 누르면 웅크리고, 다시 누르면 일어납니다. 모바일에서는 웅크리기 버튼을 사용합니다. 웅크릴 때 이동 속도, 시점, 충돌 높이와 몸통·머리 피격 범위가 함께 낮아지며, 머리 위 공간이 부족하면 일어서지 않습니다.

사용자가 제공한 `Idle Crouching.fbx`를 기존 군인 골격에 맞춰 변환한 `public/assets/crouch-idle.json`을 전투 중 반복 재생합니다. 이동할 때에는 원본 웅크린 자세에 발걸음 IK를 더하고, 서기와 웅크리기 전환을 부드럽게 연결합니다. 강화탄은 다음 목숨에 총기 피해 배율 **1.05 (+5%)**를 적용합니다.


### 전투 메뉴와 10분 제한
ESC를 누르면 로컬 전투 메뉴가 열리며, 내 이동·조준·공격·점프·웅크리기·장전·무기 교체·채팅 단축키 입력을 차단합니다. 서버와 화면 렌더링은 계속 진행하므로 상대와 AI, 이미 던진 수류탄, 피격, 자동 부활, 제한시간은 계속 진행됩니다. `전투로` 버튼이나 ESC로 메뉴를 닫으면 조작이 재개됩니다. 포인터 잠금 해제로 전달되는 ESC도 처리하며, M 채팅을 위한 잠금 해제는 메뉴를 열지 않습니다. 모바일에는 메뉴 버튼을 제공합니다.

기존 전투 상단의 두 패널은 없애고 중앙에 **내 킬 / 내 목숨 / 남은 시간 / 상대 목숨 / 상대 킬** 다섯 숫자만 표시합니다. 각 플레이어의 파랑·빨강 색은 미니맵의 내 표시색과 일치합니다. 이름·코인과 소리·로비 이동 버튼은 ESC 메뉴에 표시합니다.

서버는 맵 정찰과 3·2·1 카운트다운이 끝난 실제 전투 시작부터 600초를 계산합니다. 마지막 목숨을 잃으면 기존 승패 규칙을 적용하고, 제한시간에 도달할 때까지 승부가 없으면 킬이나 남은 목숨의 차이와 무관하게 무승부로 종료합니다. 기존처럼 마지막 전투 장면을 3초 보여준 뒤 **DRAW / 무승부**와 양쪽 킬·데스 기록을 표시하며, 확인하면 로비로 돌아갑니다. 무승부에는 패배 음악을 재생하지 않습니다.


### 로비의 단계별 게임 모드 선택
로비의 GAME MODE에는 먼저 `1vs1`, `1vsTeam`, `TeamvsTeam`을 표시합니다. `1vs1`을 누르면 같은 패널에서 `AI 훈련`과 `PVP 대전`을 선택할 수 있으며, 왼쪽 화살표로 대전 형식 선택으로 돌아갑니다. 선택 상태와 방장의 변경 권한, 두 명이 입장했을 때 AI 모드 제한은 기존 서버 규칙을 사용합니다. `1vsTeam`을 누르면 `좀비 전투`, `TeamvsTeam`을 누르면 `일반 전투`·`거점 전투`·`좀비 전투`를 같은 스타일의 하위 버튼으로 표시합니다. 새 하위 버튼은 준비 중인 비활성 버튼이며 서버 모드나 전투 기능은 연결하지 않습니다. 이 형식을 둘러보는 동안에는 게임 시작을 비활성화하고, 화살표로 돌아가 1vs1을 고르면 기존 AI/PVP 전투를 시작할 수 있습니다.

### 총구 불꽃과 피해 확인
총기 발사 때는 실제 총 모델의 총구 좌표에 약 60ms 동안 흰색 중심과 노란 불꽃을 표시합니다. 1인칭과 상대/AI에 같은 효과를 사용하며, 걷기·반동·정조준·장전 중에도 총구에 붙어 움직입니다. 연사 시 발사마다 다시 번쩍이며 칼·빈 탄창·장전 입력에는 불꽃을 만들지 않습니다. 텍스처는 한 번만 생성해 재사용합니다.

서버가 실제 피해를 처리한 `hit` 이벤트를 기준으로 공격자는 조준선 위치에 노란 **+**를 200ms 표시합니다. 피해를 받았을 때는 십자 표시를 만들지 않고 화면의 바깥 테두리를 불투명한 빨간색으로 표시합니다. 테두리 안쪽의 붉은 음영은 중앙으로 갈수록 투명해지고, 약 120ms 유지한 뒤 300ms 동안 사라집니다. 연속 피격하면 표시 시간을 갱신합니다. 총기·칼·빠른 근접 공격에 적용되며, 저격 스코프/정조준 및 마지막 처치 후 3초 종료 장면에서도 표시합니다. 벽 타격이나 부활 보호 중 무효 공격에는 명중/피격 표시를 만들지 않습니다.


### 연결 안정성과 전투 복구
입력은 키/클릭 이벤트가 겹쳐도 최대 30Hz로 묶어 전송하고, 보낸 입력에만 로컬 이동 예측을 적용합니다. 입력 사이의 짧은 발사 탭은 보관해 다음 입력에 포함합니다. 서버는 정상적인 짧은 입력 폭주에 연결을 끊지 않고, 전송 대기량이 커지면 오래된 상태 패킷을 더 쌓는 대신 새 상태 전송을 잠시 건너뜁니다.

예상하지 못한 연결 종료 시 좌석과 서버의 경기 상태를 60초간 유지하고, 비공개 세션 토큰으로 같은 플레이어가 자동 재연결합니다. 상대방의 소켓이나 방을 즉시 삭제하지 않습니다. 재접속은 끊기기 전 입력을 재전송하지 않고 서버의 현재 위치·HP·목숨·탄약·전적·시계와 입력 순번으로 이어 갑니다. 재연결 중에도 서버의 전투와 제한시간은 계속 진행됩니다. 앱 수준 ping/pong과 재시도 시간 제한으로 응답 없이 열린 소켓도 복구합니다.

현재 탭을 새로고침한 경우 세션 정보를 sessionStorage에서 읽어 3D 에셋이 준비된 뒤 전투로 복귀합니다. 새 탭은 기존 플레이어를 자동으로 빼앗지 않습니다. 세션 토큰은 방 목록이나 상대에게 전송하지 않으며 로그에도 기록하지 않습니다. 명시적인 방 나가기는 재연결과 구분합니다.

서버 프로세스 자체가 재시작되면 메모리의 방은 사라집니다. 이런 경우나 복구 대기 시간이 끝난 경우 첫 화면으로 강제 이동하지 않고 현재 화면에 안내와 `방 메뉴로` 버튼을 표시합니다. 소켓 종료 코드·입력 제한·재연결 사건은 세션 비밀 없이 서버 로그에 기록합니다.


### 방 비밀번호
로비의 초대 코드 옆에 방 비밀번호 입력 칸과 저장 버튼이 있습니다. 방장만 로비에서 1~24자 비밀번호를 설정·변경할 수 있고, 빈칸을 저장하면 비밀번호를 해제합니다. 다른 참가자에게는 설정 여부만 표시합니다.

공개 방 목록에는 비밀번호가 있는 방을 잠금 표시로 구분합니다. 해당 방을 선택하면 입력창을 띄워 비밀번호 확인 후 참가합니다. PRIVATE의 코드 참가 화면에도 비밀번호 입력 칸이 있으며, 코드만 알고 있는 경우에도 서버의 비밀번호 검사를 우회할 수 없습니다. 잘못 입력하거나 확인 중 비밀번호가 바뀌면 자리를 배정하지 않고 재입력을 안내합니다.

서버는 별도 난수 salt와 scrypt 해시만 메모리에 보관하고, 비밀번호나 해시를 방 목록·전투 상태·로그·sessionStorage에 싣지 않습니다. 확인 작업은 비동기로 처리하고, 완료 직전에 방의 인원·상태·비밀번호 버전을 다시 확인합니다. 기존 플레이어의 세션 토큰에 의한 재연결에는 재입력을 요구하지 않습니다. 이미 참가한 플레이어에게는 변경된 비밀번호를 다시 묻지 않으며, 비밀번호는 다음 경기에도 유지됩니다.
